# 第三阶段手动验收清单

仅操作 TaskDock。建议使用“阶段三验收”前缀任务。先保存需要保留的草稿；测试记录可正常软删除，不修改 SQLite 文件。

## A. 第二阶段遗留：跨窗口编辑冲突

1. 创建一个计划今天、未完成的测试任务（不带子任务或先完成子任务），打开悬浮窗。
2. 主窗口打开任务详情，修改描述为“冲突验收草稿”，不要保存。
3. 在悬浮窗勾选同一任务，使其完成。
4. 返回主窗口：描述草稿应完整保留，显示其他窗口已修改的提示，“保存任务”禁用，阻止旧版本覆盖。
5. 若事件尚未抵达而保存按钮仍可用，立即点保存：应返回 CONFLICT，仍保留草稿，不显示已保存。
6. 点“放弃草稿并重新载入”：应显示已完成状态及数据库原描述。可在已完成视图撤销完成。

保存被禁用是正常的主动冲突防护，不必绕过 UI 强行点击。自动化工具若激活失败，重新选窗口后只重试一次，仍失败则记录工具错误并改手测，不判定软件失败。

## B. 托盘与退出

1. 启动 release/taskdock.exe，关闭主窗口：主窗口隐藏、TaskDock 进程仍在、通知区域存在托盘图标。
2. 右键托盘，逐项检查“打开主窗口”“快速添加任务”“显示/隐藏悬浮窗”“打开设置”。
3. 双击托盘图标：主窗口显示、取消最小化并聚焦。
4. 设置里把“关闭主窗口时”改成“退出 TaskDock”并保存，再关闭：进程应退出。重新打开后可改回“隐藏到系统托盘”。
5. 托盘“退出 TaskDock”：所有 TaskDock 窗口关闭，任务管理器无 taskdock.exe 残留。重新启动，数据保留。

## C. 全局快捷键

1. 默认 Ctrl+Alt+T 打开快速输入；输入焦点在标题框，可立即键入。
2. Esc 隐藏快速输入，不退出应用。连续按快捷键只使用同一窗口。
3. 隐藏主窗口，保持普通办公软件活动，再按快捷键：仍能打开快速输入。
4. 设置里改成 Ctrl+Alt+Y 并保存：新键可用，旧键不再响应；测试后改回默认。
5. 使用另一程序占用候选键，在 TaskDock 保存该候选键：提示 SHORTCUT_CONFLICT，保留旧有效键、原持久化值及当前输入。
6. 退出 TaskDock 后快捷键不再被占用。测试冲突只在已知测试程序上操作，不修改系统快捷键或安装键盘钩子。

## D. 悬浮窗与多屏

1. 默认内容尺寸 320×400，不强制置顶；拖动标题的空白/文字区可移动，勾选和刷新等按钮不会触发拖动。
2. 拖动右下角斜线缩放，可缩到 260×220；最大限制 600×800。小尺寸内容压缩，任务区内部滚动，底部快速添加仍可使用。
3. 软件设置调整不透明度到 60% 并保存：整个悬浮窗半透明；改回 100% 恢复。勾选置顶并保存，在其他窗口前验证；测试后可关闭。
4. 改位置/大小，等待至少 1 秒，显式退出后重启：尺寸、位置、可见性、透明度及置顶恢复。
5. 设置“恢复窗口默认位置”：三个窗口回到当前主显示器安全工作区；不改变任务、分类或主题。
6. 双屏（含负坐标）与不同 DPI 下移动窗口，退出重启；拔掉原屏/改变分辨率后启动或等待工作区检测，主要交互区域应可见。
7. 本机无第二屏或特定缩放环境时，将该项标为待验收，不能用几何单测代替真机结论。

## E. 开机启动与单实例

1. 默认开机启动关闭，启动软件本身不会新注册启动项。
2. 在软件设置显式勾选并保存：系统启动项显示启用；重复保存不产生重复 Run 值，不要求管理员权限。
3. 显式退出，再以 --background 参数启动：主窗口不强制显示；仅按已保存的悬浮窗显示设置显示 widget。实际 Windows 注销/登录应同样后台启动，需单独验收。
4. 设置里关闭开机启动并保存：系统启动项关闭。测试后保留用户原选择，不擅自保持开启。
5. 已运行时再次启动 exe：原实例主窗口显示/聚焦，只有一个 taskdock.exe、三个预声明窗口和一个数据库服务。

## F. 回归与主题

1. 悬浮窗完成/撤销测试任务，主窗口同步；主窗口编辑计划日期等数据，悬浮窗相应更新。
2. 主窗口软件设置与侧栏外观均可切换明亮/深色，三个窗口同步；打开设置时无重复 label/id。
3. 保存桌面设置失败时不显示成功，保留输入；外部设置变化时要求重新载入，不能旧值覆盖。
4. 任务、分类、子任务及审计数据不因窗口/托盘设置变化而丢失。

记录格式：项目编号、系统/显示器/DPI、点击步骤、实际结果、错误代码、通过/失败/待验收。阶段三报告只记录实际完成项，通知/提醒/重复/备份/安装器仍在后续阶段。
