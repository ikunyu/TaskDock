# 第三阶段实施基线

授权范围：托盘、全局快捷键、悬浮窗口交互与状态、多显示器恢复、显式自启动、统一设置、单实例。保留任务 LocalService 和设置 revision 事件，不修改迁移 0001/0002，不进入第四阶段。

实施顺序：核对官方 API → Schema 3 设置/窗口状态及纯几何测试 → Rust 桌面运行时/受限 IPC → 现有 Pinia 设置与 Vue 界面 → 自动化回归/Release → 可行的 Windows 原生检查与报告。

设计：设置沿用 app_settings.revision；窗口几何单独记录避免每次移动广播任务/主题。持久化逻辑尺寸和物理坐标，并保存缩放因子；恢复时使用当前显示器工作区及缩放重新约束。快捷键变更新注册成功后才移除旧注册，失败保留旧值；OS 副作用与数据库写入不能跨系统原子提交，使用补偿并记录实际运行状态。显式退出保存几何、注销快捷键、关闭数据库。启动项默认关闭，只有用户设置操作可修改 OS 注册。

第二阶段冲突复现：1）选一个计划今天的未完成测试任务，打开主窗口详情并修改描述但不保存；2）悬浮窗完成同一任务；3）返回主窗口，确认草稿仍在、出现版本更新提示、保存被禁用；4）若事件延迟，直接保存应返回 CONFLICT 而非覆盖；5）选择重新载入后显示新状态。工具激活失败最多恢复一次，不能把工具失败当应用失败。

测试：保留前端 58 项/Rust 21 项回归；增加迁移升级/非法设置、几何负坐标/缩放/离屏、快捷键替换补偿、设置失败草稿和同步测试；执行 typecheck、Vitest、Rust test/fmt/Clippy、Release。Windows 10、混合 DPI、多屏插拔及真实登录启动如无法实测明确待验收。
