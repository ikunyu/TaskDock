# TaskDock 1.1.1 安装与使用

悬浮窗展开后，事项名称和日期/时间同一行显示，名称更大、日期较小且淡色；长名称悬停可查看全文，日期悬停显示完整安排及截止信息。

悬浮窗进一步收窄：默认宽200逻辑像素，最小180，收起自适应宽上限200。布局、字号及顺序保持不变；旧220/240/320宽度自动采用新默认，其他保存宽度保留。

悬浮窗保留页签、周分组、字号和操作布局，压缩空白间距；展开后内容少时收缩高度，内容多时任务区滚动，展开宽度仍保留你的设置。

悬浮窗默认展开宽240逻辑像素，可缩至220，收起内容宽最多240；周标题更大、事项更小。今日/未来勾选后保留原位删除线，再点可撤销，不再完成后下移。若旧版保存的是320默认宽，恢复时采用新窄默认；其他手动尺寸仍保留。

周会查看任务：从侧栏打开“周概览”，按周一至周日查看。周一开会时点击“上一周”查看上周，再“返回本周”查看本周安排；支持分类/状态筛选；每日一行，先显示两项，其余点“+N”展开。详见[周概览说明](weekly-overview.md)。

日期字段支持“今天 / 明天 / 一周后”；右侧日历按钮可直接输入年份及切换月份，选远期日期无需反复滚动。也可在日期框直接输入。

新建任务的日期只能选择今天及以后；过去的任务记录仍可查看和编辑。任务右侧空框表示未完成，点击并保存成功后显示对勾，再次点击可撤销；有未完成子任务时会先要求确认。

到期未完成的事项会自动显示红色“超时任务”，在主窗口今天和悬浮窗今日中优先排列；小窗收起时显示“超时 · 标题”。只设截止日期时当天结束后超时；无截止则按安排日期判断。达到截止时刻、重新打开或聚焦后会刷新，系统休眠期间不会实时重绘。

任务删除会先要求确认，确认后永久删除，无法撤销。主界面不再显示“已删除”，旧版软删除记录仍保留，不自动清理；重复任务只删除当前实例。

支持目标：Windows 10/11 x64，需要 Microsoft Edge WebView2。此版本已构建，尚未执行安装、运行或功能验收；未数字签名，Windows可能提示未知发布者。构建成功不代表功能已全部验证。

## 安装

1. 如旧版正在运行，先从托盘或软件设置退出TaskDock；关闭主窗口通常只是隐藏。
2. 运行 `TaskDock_1.1.1_x64-setup.exe`。默认仅安装到当前用户，通常不需管理员权限，安装向导可能默认显示 `%LOCALAPPDATA%\TaskDock`；为避免任务数据保存在C盘，请在目录页改选 `F:\TaskDock`、`D:\TaskDock` 等可写目录。支持简体中文和英文。
3. 已安装WebView2时直接复用；缺少时使用内嵌微软引导程序联网下载。此安装包不是离线WebView2完整包，企业策略可能限制运行时安装。
4. 完成页的运行选项默认不勾选，由用户选择何时首次启动。可从开始菜单TaskDock打开。

程序数据现在跟随实际EXE所在文件夹：`data\taskdock.sqlite3`包含任务/分类/子任务/设置/提醒/规则/历史，备份在`data\backups`，日志在`logs`，WebView缓存在`webview`。应用标识com.taskdock.desktop不变。安装包不携带数据库或备份，不会覆盖用户已有data文件夹。若软件本身装在C盘，数据仍在C盘；请主动选择非C盘目录。

首次启动时，如果新data目录无数据库，会从旧`%LOCALAPPDATA%\com.taskdock.desktop`只读创建SQLite一致性快照，在新盘暂存并迁移到Schema8，校验任务/设置、完整性/外键并逐份复制校验备份后，再启用新data目录。原C盘文件不删除、不升级；已有新数据库不覆盖。如果旧库缺失但有恢复日志、WAL/SHM或备份，或新data非空却无数据库，会报错并保留文件，不创建空库顶替。迁移失败修复空间/权限等问题后重启，保留`.taskdock-import-*`暂存文件。本轮开发未启动软件或执行真实迁移。

按统一版本要求，本次安装器允许覆盖此前较高的应用版本；数据库 Schema 仍按原有迁移与兼容性检查管理，不进行数据库降级。升级前退出旧进程；若出现进程占用提示，请正常退出后重试。已存在的TaskDock开机启动项会更新到安装目录，未开启时不创建启动项。完整安装/升级/卸载和注册表实际行为仍待手动验收。

## 基本使用

- “任务”入口中切换“今天 / 未来事项”，统一从“新建任务”选择安排日期；未来事项到了当天会自动出现在今天。心愿单单独保存无固定日期的愿望，实现后划掉并保留记录；已完成列表仅显示有安排日期的任务。
- 新建或点击任务进入详情，设置截止日期、截止方式、优先级、分类、子任务、提醒和重复。仍有未完成子任务时完成父任务需确认。
- 左侧保留月历和周概览，已移除搜索与筛选；已移除操作历史页面及任务详情中的历史按钮。
- Ctrl+Alt+T打开快速输入，Enter添加，Esc隐藏。快捷键冲突时可在设置换一个组合；这只影响快捷唤起，不应影响主窗口按钮、托盘或悬浮窗显隐。
- 悬浮窗默认收起，缩小为显示今日任务及已完成删除线的小窗；点击“展开”显示“今日 / 未来事项”页签、进度和快速添加，点击“收起”回到只含任务标题的小窗；左键拖动标题空白处，展开后可用右下角缩放。透明度、置顶及显隐在设置中保存；拖动缩放和多屏行为仍待真机确认。
- 默认关闭主窗口隐藏到托盘，调度继续运行；使用托盘/设置的退出操作结束进程。
- 设置分为外观与桌面、数据管理、关于与运行状态。系统通知被屏蔽时，可在应用内提醒中心查看。
- 外观主题同时用于页面和原生标题栏；跟随系统会恢复 Windows 自动主题。左侧菜单独立滚动，顶部品牌与底部主题选择保留可见。
- 自动备份默认开启，每24小时一次、保留30份自动备份；手动及恢复前安全备份保留。详见 [数据管理说明](data-management.md)。恢复会替换数据，必须明确确认；本版恢复失败路径尚未做实际故障验证。

## 卸载与保留数据

通过Windows“已安装的应用”卸载TaskDock。默认卸载不清理应用数据；**不要勾选卸载界面的“删除应用数据”选项**，即可保留任务数据库和备份。升级模式也不清理该目录。安装器不会要求用户通过删库修复问题。

卸载会移除程序和快捷方式，正常卸载还会清理TaskDock启动项。后续重装仍可使用保留的数据。上述为生成的安装脚本静态核对结果，本次没有运行卸载器验证。

## 开发者构建

```powershell
. .\scripts\Use-LocalToolchain.ps1
npm ci
npm run typecheck
npm run package:windows
```

工具链为Node24、Rust MSVC、Windows SDK。`package:windows`执行前端生产构建、Rust Release和NSIS；不启动软件。Tauri会下载必要NSIS工具及WebView2引导程序。依赖版本由锁文件固定。

悬浮窗的未来事项按周一至周日分组，显示本周、下周及日期范围。各处空列表直接留白；错误和删除/恢复确认等必要反馈保留。

悬浮窗字号可在“软件设置 → 外观与桌面 → 悬浮小组件”分开调整：展开任务、收起任务、任务日期/时间、周标题和周日期范围。保存桌面设置后生效并重启保留；“默认字号”只重置当前输入，仍需保存。悬浮窗默认宽180，收起后也可选择“今日 / 未来”，未来按周分组。Schema7首次迁移保留任务与备份记录；旧程序不能直接打开更高Schema的新库。

## 同一任务定期提醒

在任务详情的“提醒与重复”中勾选“定期提醒同一任务”，选择首次提醒时间，再选择预设或填写“每隔”数值及分钟/小时/天。比如首次设明天09:00、每隔1天，就从明天开始每天同一时刻提醒当前任务，无需开启下方“任务重复周期”。按天保留本地钟点，分钟/小时按实际经过时间计算。间隔为正整数，最长3650天。

任务完成、删除、取消所有提醒，或到达完成日期的截止时间后，定期提醒停止；撤销完成会恢复后续周期。软件完全退出期间不发送，重开或唤醒时仅合并补发最近一次；已过截止的不补发。提醒中心同一任务只保留最新周期提醒供处理，“已知晓”只处理当前次，“稍后提醒”不会改变后续固定周期。修改后点击保存才生效。

日期名称统一为“截止日期”。截止方式仍为“无截止 / 仅日期（当天结束前）/ 精确时间（本地时间）”，位于分类上方。仅日期沿用上方日期，不再填写第二个日期，截止/提前提醒按本地23:59计算；精确时间恢复原来的日期时间选择器，与上方日期同步。无截止不设置额外的截止/提前提醒，上方日期仍用于任务归属及基础跨日超时；指定时间和定期提醒保留原规则。

旧版记录不会自动批量改写。有独立截止日期/时间的旧任务，详情显示原截止值；只改标题等内容保留原日期字段，主动修改日期/方式/时间才统一为新的截止日期。心愿单继续不要求日期。

悬浮小组件不单独显示任务栏图标，Windows设置为“不合并任务栏按钮”时也按此配置；主窗口仍保留正常任务栏入口。关闭主窗口隐藏后，可从系统托盘重新打开主窗口、切换悬浮窗或退出程序。

## 移动软件与保存数据

更新到同一文件夹时替换EXE或运行安装包即可，保留data。需要更换盘符、拷贝到另一台电脑时，先从托盘退出，再复制整个软件目录，至少包含EXE和完整data目录（连同可能存在的WAL/SHM、备份及恢复文件），然后从新位置启动；不要只复制正在写入的数据库文件。新设备会使用复制过去的数据，不会自动把另一台电脑任务同步过来。两个软件副本各自使用身边的data，单实例保护仍然生效。

默认卸载保留data/logs/webview，安装目录因为这些文件非空可能仍保留。不要手工删除data；不需要的旧C盘副本需在你确认新位置数据完整后自行管理，本程序不自动删除。已开启的开机启动入口在新位置启动时更新到当前EXE；原来未开启的不会因移动软件而开启。目录不可写时提示检查位置/权限，不改回C盘。

## 软件内更新

首次使用本功能，需要先在每台旧设备安装一次支持更新的新版本。之后打开TaskDock会后台检查GitHub，有新构建时主窗口顶部显示提示，也可在“软件设置 → 关于与运行状态”点击“检查更新”。界面版本仍为1.0.0，以内部构建号识别新旧。

先点击“下载更新”，下载与签名验证成功后才出现“安装并重启”。确认前保存所有窗口的未保存内容；更新正常关闭数据库和快捷键，再在当前软件目录运行安装器并重启。任务和data/backups继续保留，不改换盘符、不上传任务数据。网络或签名错误会显示原因并保留旧软件；无法连接GitHub时可稍后再试或手动下载安装包。Windows系统仍可能因未做Authenticode签名显示未知发布者，更新包的密码学签名校验与Windows发布者证书不同。

## 从1.0.0或1.0.1检查本次更新

使用已包含GitHub更新功能的1.0.0或1.0.1，在软件设置→关于与运行状态点击“检查更新”，然后“下载更新”。保存所有窗口草稿后点“安装并重启”；重新打开设置应显示TaskDock 1.1.1。不要先手动换新版EXE，否则无法体验旧版到新版的更新流程。此流程待用户实际验证。更新协议中的1.0.0+构建号及下载地址中的1.0.0文件名用于兼容旧更新器；实际安装包内容和软件版本均为1.1.1。
