# TaskDock 1.0.0 永久删除

日期：2026-10-30。数据库仍为 Schema 5。

## 使用

主窗口任务列表点击任务右侧删除按钮，或在详情中点击“删除任务”，都会先显示任务标题和“永久删除，无法撤销或恢复”的确认。取消不修改数据，只有点击“永久删除”才执行。详情有未保存草稿时会额外提醒，删除失败保留确认框、错误及草稿。

不再显示“已删除”入口，也不再将新删除的任务移入回收站。旧版本已有的软删除记录仍保留在原数据库中，常规列表不显示，不批量清理。

永久删除会从当前数据库移除任务、子任务、提醒、调度关联及其审计记录。分类、其他任务、设置和已有备份不受影响；用户主动恢复旧备份仍可能带回任务，这不是磁盘级安全擦除。

重复任务只删除当前实例，后续实例继续生成。删除事务保留原系列中的排除日期，防止同一实例再次生成；提醒去重账本保留。

## 实现与检查

- 列表与详情复用 DeleteTaskDialog，Pinia 调用现有 purge_task。Rust 只允许 main 调用，校验确认参数、UUID、版本并在 mutate_tasks 同一事务中更新排除项和删除关联记录；失败回滚 revision 与数据。
- 移除前端软删除/恢复流程和旧 set_task_deleted IPC/权限。旧版 deleted_at 字段、记录及已发布迁移不变，内部重复规则的软删除逻辑保留。
- 新增永久删除的确认/失败保留草稿交互用例，以及未确认/版本冲突/保留旧记录/事务回滚的 Rust 用例；本轮仅编译，不执行测试。
- 实际静态检查与正式构建结果见 stage-6-report.md；没有启动应用、运行测试或访问真实用户数据库。

交付仍为 1.0.0；EXE 与安装包更新后使用。运行中的旧版需先从系统托盘退出再替换。
