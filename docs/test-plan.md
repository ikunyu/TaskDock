# 测试计划

## 第二阶段自动检查

| 层级      | 命令                                                                                    | 重点                                                    |
| --------- | --------------------------------------------------------------------------------------- | ------------------------------------------------------- |
| 类型      | npm run typecheck                                                                       | Vue SFC、严格 TS、IPC 契约                              |
| 前端      | npm test                                                                                | 原设置回归、任务过滤/日期、同步竞态、交互失败草稿与确认 |
| 格式      | npm run format:check                                                                    | 前端、JSON、Markdown                                    |
| Rust 格式 | cargo fmt --manifest-path src-tauri/Cargo.toml -- --check                               | Rust 风格                                               |
| Rust 业务 | cargo test --manifest-path src-tauri/Cargo.toml --locked                                | 原迁移/设置回归、Schema 2、任务事务、审计、并发与持久化 |
| Rust lint | cargo clippy --manifest-path src-tauri/Cargo.toml --all-targets --locked -- -D warnings | 全目标严格检查                                          |
| 原生构建  | npm run tauri -- build --no-bundle                                                      | 含 typecheck/Vite 的 release、ACL/配置有效性            |

`npm run tauri -- info` 记录实际环境；使用项目工具链时先 `. .\scripts\Use-LocalToolchain.ps1`。所有失败必须修复后复跑；原生可执行文件启动和交互需单独验收，不能用浏览器模拟替代。

## 第二阶段验收矩阵

| 场景                | 自动化方法                                         | Windows 原生方法                   |
| ------------------- | -------------------------------------------------- | ---------------------------------- |
| 创建/编辑/删除/恢复 | Rust 生命周期/审计、前端恢复交互                   | 主窗口保存、已删除列表恢复         |
| 四视图/计划改变     | 日期函数与主窗口列表测试                           | 快速添加收集箱及今日任务           |
| 跨天未完成与逾期    | 固定日期、跨天/时区测试                            | 不修改真实系统时钟；跨夜长跑待验收 |
| 完成/撤销           | Rust 状态及完成时间、前端 checkbox                 | 主窗口与 widget 双向操作           |
| 子任务/父进度/确认  | Rust 聚合排序/进度、前端编辑与确认                 | 0/1→1/1，父任务仍未完成            |
| 分类删除保任务      | Rust 引用清空、版本及审计                          | 临时分类关联任务后删除分类         |
| 窗口双向同步        | 两 Pinia store、乱序/合并刷新                      | 后台窗口不聚焦仍观察计数/状态变化  |
| 保存失败状态        | bridge 注入失败、草稿/旧提示/checkbox 检查         | 不故意损坏真实用户库               |
| 持久化              | 数据库关闭重开                                     | release 退出重启，保留记录         |
| 迁移                | Schema 1 升级、幂等、坏迁移回滚、空库下行/非空拒绝 | 旧用户库实际升级，核查原设置       |
| 快速并发            | 两连接冲突与 30 次独立写入；store 乱序测试         | 未执行三窗口高频压力长跑           |
| 明暗主题            | 既有主题/乱序事件测试                              | 主/悬浮/快速窗视觉与主题同步       |

Rust 测试在 tempfile 数据库内执行；注入失败触发器仅用于临时库，禁止破坏真实库。前端测试采用 Vitest + Vue Test Utils + jsdom，不等同于 WebView2 E2E。完整实际命令、数字和证据在 stage-2-report.md。

## Windows 待验收及阶段边界
