## 已实现

- 指定日期时间、截止时、提前10/30/60/1440分钟提醒；提醒中心和详情抽屉支持稍后10/30/60分钟；可取消所有提醒并保存。
- 提醒使用稳定UUID、持久状态和逻辑slot；普通标题编辑不重发。任务完成、软删除或取消提醒会停止对应待发送提醒。截止提醒随截止变更重算，关联的指定提醒随计划日移动。
- Tauri v2 Windows系统通知，包含标题与内容；单任务通知携带taskId，点击在系统支持范围内聚焦已有主窗口、打开详情。有未保存详情时保留草稿并提示。合并通知打开主窗口提醒中心。
- 持久化应用内提醒中心始终可用，作为禁止通知、免打扰或系统投递失败时的替代；任务列表展示下次提醒、待处理提醒与重复标识。
- 每日、指定星期、指定月日期、自定义天数间隔，支持间隔和结束日期/无限；不足31日的月份取最后一天。每个实例和子任务使用独立UUID，子任务初始未完成，保留不同日期的完成历史。
- 编辑范围“仅此一次”保留系列模板；“此次及此后”切分系列、保留完成历史与日期排除集，软删除待替换的未完成实例，再分批按新模板生成。选择不重复并保存此后范围可结束系列。
- 后台线程复用唯一LocalService与原生命周期；隐藏到托盘后继续调度，重启/休眠后按当前时间补齐。默认预生成32天；更早提醒扩大生成范围，避免下一实例提前提醒被延迟生成。
- 事务内认领最多500条到期提醒、合并为一条通知，两条通知至少相隔30秒。每批最多生成50实例、处理20系列，每系列扫描最多366天；长时间离线分多轮补齐。

## 数据库与技术方式

新增 `0004_scheduling.sql`，不修改0001/0002/0003，不重建用户任务表：

| 表                | 内容                                                                                                   |
| ----------------- | ------------------------------------------------------------------------------------------------------ |
| recurrence_series | 规则/模板JSON、起止日、持久游标、版本、有效状态、完成日期排除集                                        |
| task_schedule     | 任务外键、提醒/重复配置、系列外键、不可变实例日期；系列+日期唯一                                       |
| reminders         | UUID、任务外键、slot、UTC时间、pending/notified/cancelled/dismissed、发送通道及认领时间；任务+slot唯一 |

设置、实例生成、提醒状态和对应审计沿用IMMEDIATE事务、task_state.revision与既有事件同步；不另建数据库或前端状态服务。重复唯一键和游标同事务提交。新下行脚本仅供开发者显式事务使用，调度表非空即拒绝，应用无生产下行IPC。

纯日期保持日历字符串；精确时间为UTC。重复生成按本机当前时区保留墙钟时间，DST重叠选首次、缺失时间顺延到当天有效分钟；特殊跨日期跳变仍可能报错并保留数据。纯日期截止按本地23:59。

通知插件精确锁定2.8.0，已核对官方页面和实际依赖源码。插件桌面权限查询始终Granted，不能据此识别Windows屏蔽；因此始终保留应用内替代方案。只有main新增两个受限IPC权限，WebView没有通知插件、SQL或文件系统权限。三窗口、单实例、托盘退出设计保留。

notified表示提醒已进入应用内中心并认领发送机会，channel=unknown，不表示系统实际展示。认领事务提交后崩溃可能只留下应用内记录；重启不重复发送该提醒。提交给系统前在数据库锁内再次检查取消/完成状态；插件随后异步派送，已交给OS的toast不保证撤回。delivered_at预留，未伪造送达回执。
